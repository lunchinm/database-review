一、选择题（每题 2 分，共 40 分）

1. WAL 协议的核心要求是什么？

✓ 正确！ WAL (Write-Ahead Log) 要求日志记录必须先于数据修改写入稳定存储。

2. 系统故障（如断电）的恢复方式是？

✓ 正确！ 系统故障需UNDO未提交事务+REDO已提交但未写盘的事务。

3. 日志记录 <T, X, 10, 20> 的含义是？

✓ 正确！ 格式 <T, X, old, new> 表示T将X从old改为new。

4. UNDO 操作的扫描方向是？

✓ 正确！ UNDO从后往前（逆序撤销），REDO从前往后（顺序重做）。

5. 检查点 (Checkpoint) 的主要作用是？

✓ 正确！ 检查点将脏页写盘并记录活跃事务，恢复时只需从最后一个检查点开始扫描。

6. 向量数据库的核心查询方式是？

✓ 正确！ 向量数据库基于近似最近邻(ANN)进行相似性搜索，而非精确匹配。

7. 以下哪个是向量数据库常用的索引算法？

✓ 正确！ HNSW(分层可导航小世界)是向量数据库最主流的ANN索引算法。

8. 余弦相似度的取值范围是？

✓ 正确！ 余弦相似度∈[-1,1]，1=完全相同方向，-1=完全相反，0=正交。

9. ARIES 恢复算法的三个阶段顺序是？

✓ 正确！ ARIES: 分析(确定列表)→REDO(重做已提交)→UNDO(撤销未提交)。

10. 介质故障的恢复方式是什么？

✓ 正确！ 介质故障需从备份恢复数据，再用日志REDO备份后的修改。

11. WAL 协议中，事务提交前必须满足什么？

✓ 正确！ WAL要求事务提交前所有日志记录必须已持久化到稳定存储。

12. Embedding 在向量数据库中的作用是？

✓ 正确！ Embedding将文本/图像等非结构化数据转为高维向量，语义相似的向量距离近。

13. UNDO-REDO 恢复策略的特点是什么？

✓ 正确！ UNDO-REDO最通用，数据可以在提交前或提交后写盘，现代数据库大多采用此策略。

14. PQ (Product Quantization) 的主要作用是？

✓ 正确！ PQ通过量化将向量压缩为更小的表示，大幅减少内存占用。

15. 检查点日志记录的格式是？

✓ 正确！ <checkpoint L>其中L是当前活跃事务列表，用于恢复时确定UNDO范围。

16. RAG (检索增强生成) 的工作流程是？

✓ 正确！ RAG=检索+生成：先将知识库向量化，查询时检索相关片段，结合LLM生成准确回答。

17. 以下哪种情况需要 REDO 操作？

✓ 正确！ REDO用于已提交但数据可能未写入磁盘的事务。B需要UNDO，C无需操作。

18. LSH (Locality-Sensitive Hashing) 的特点是什么？

✓ 正确！ LSH通过哈希函数将相似向量映射到同一桶，速度快但精度不如HNSW。

19. 检查点越频繁会导致什么？

✓ 正确！ 检查点越频繁恢复越快，但正常运行时写盘开销越大。需要权衡。

20. 关于向量数据库，以下说法正确的是？

✓ 正确！ 余弦相似度关注方向，对向量长度不敏感。欧氏距离对长度敏感。HNSW精度最高。

二、判断题（每题 1 分，共 10 分）

21. WAL 协议要求数据修改先于日志记录写入磁盘。

✗ 错误！ WAL 要求日志先于数据写盘（Write-Ahead Log = 日志先写）。

22. 事务故障只需要 UNDO 操作来恢复。

✓ 正确！ 事务故障只影响单个事务，撤销其修改即可（UNDO），无需REDO。

23. REDO 操作从后往前扫描日志。

✗ 错误！ REDO从前往后（顺序重做），UNDO从后往前（逆序撤销）。

24. 检查点可以完全消除恢复需求。

✗ 错误！ 检查点只是减少恢复范围，不能消除恢复需求。仍需UNDO未提交事务+REDO已提交事务。

25. 向量数据库使用 ANN（近似最近邻）而非精确搜索。

✓ 正确！ 高维向量精确搜索代价极高，ANN在精度和速度间权衡，是向量数据库的核心技术。

26. UNDO-REDO 策略要求数据只能在事务提交后写盘。

✗ 错误！ UNDO-REDO 最通用，支持任意写盘时机（提交前或提交后都可以）。

27. HNSW 算法精度高但内存占用较大。

✓ 正确！ HNSW 构建分层图结构，精度是ANN算法中最高的之一，但需要存储所有向量和图层连接。

28. 介质故障比系统故障更容易恢复。

✗ 错误！ 介质故障（磁盘损坏）恢复最困难，需要从备份恢复+REDO，且可能丢失部分数据。

29. 余弦相似度值为1表示两个向量完全相同。

✗ 错误！ 余弦相似度=1表示方向完全相同，但长度可以不同（如[1,1]和[2,2]余弦相似度=1）。

30. ARIES 恢复算法的 UNDO 阶段在 REDO 阶段之前执行。

✗ 错误！ ARIES顺序：分析→REDO→UNDO。先REDO再UNDO确保恢复的正确性。

三、填空题（每题 2 分，共 20 分）

31. WAL 全称是 。

答案：Write-Ahead Log — 日志先写协议。

32. 三类故障：事务故障、系统故障和 。

答案：介质故障 — 磁盘损坏，恢复最困难。

33. 日志记录格式 <T, X, old, new> 称为 记录。

答案：Update / 更新 — 记录数据修改的前后值。

34. 操作撤销未提交事务的修改。

答案：UNDO — 从后往前扫描，恢复旧值。

35. 检查点将 页写入磁盘。

答案：脏 / Dirty — 缓冲区中被修改但未写盘的数据页。

36. 向量数据库的核心查询方式是 （缩写）。

答案：ANN — Approximate Nearest Neighbor，近似最近邻搜索。

37. 算法通过分层图结构实现高精度ANN搜索。

答案：HNSW — Hierarchical Navigable Small World。

38. 是将非结构化数据映射为固定维度向量的技术。

答案：Embedding / 嵌入 — 语义相似的输入对应空间距离近的向量。

39. ARIES 恢复三个阶段：分析、、UNDO。

答案：REDO — 顺序：分析→REDO→UNDO。

40. 全称是 Retrieval-Augmented Generation（检索增强生成）。

答案：RAG — 向量数据库的典型应用场景。

四、简答题（每题 5 分，共 20 分）

41. 简述 WAL 协议的两条核心规则及其意义。

参考答案：规则1：对数据项的修改，其日志记录必须先写入稳定存储。规则2：事务提交时所有日志记录必须先刷盘。意义：保证崩溃后可以通过日志恢复——如果数据写盘前崩溃，日志中有修改记录可以REDO；如果事务未提交就崩溃，日志中无COMMIT记录可以UNDO。

42. 简述 ARIES 恢复算法的三个步骤及各步骤的作用。

参考答案：1.分析阶段：从最后一个检查点开始扫描日志，确定UNDO列表（未提交事务）和REDO列表（已提交事务）。2.REDO阶段：从前往后重做所有已提交事务的操作，确保持久性。3.UNDO阶段：从后往前撤销所有未提交事务的操作，确保原子性。先REDO再UNDO保证恢复后数据库一致。

43. 对比向量数据库和传统关系数据库在数据类型、查询方式和索引方面的区别。

参考答案：数据类型：传统库存结构化数据（数字/字符串），向量库存高维Embedding向量。查询方式：传统库用精确匹配/范围查询，向量库用相似性搜索(ANN)。索引：传统库用B+树/哈希，向量库用HNSW/IVF/PQ。向量数据库牺牲精确性换速度，适合AI时代的非结构化数据检索。

44. 简述检查点的作用及带检查点的恢复流程。

参考答案：检查点作用：将缓冲区脏页写入磁盘，记录活跃事务列表，减少恢复时需扫描的日志量。恢复流程：从最后一个检查点开始扫描→检查点前已提交事务无需处理（数据已在检查点时写盘）→检查点列表中未提交事务需UNDO→检查点后事务根据COMMIT状态决定UNDO或REDO。检查点越频繁恢复越快但运行开销越大。

五、综合题（10 分）

45. 系统崩溃后日志如下（从上到下为时间顺序）：
<T1, start>, <T1, A, 10, 20>, <T2, start>, <T2, B, 5, 15>, <checkpoint {T1,T2}>, <T1, C, 30, 40>, <T1, commit>, <T2, D, 0, 10>

(1) 恢复时从哪条记录开始扫描？
(2) 哪些事务需要 UNDO？哪些需要 REDO？
(3) 简述各数据项的最终值及理由

参考答案：
(1) 从<checkpoint {T1,T2}>开始扫描。
(2) REDO列表：T1（有commit记录）→重做T1的所有操作。UNDO列表：T2（无commit记录，在检查点活跃列表中）→撤销T2的所有操作。
(3) T1的修改(A:10→20, C:30→40)已提交需REDO，最终A=20, C=40。T2的修改(B:5→15, D:0→10)未提交需UNDO，最终B=5, D=0。
