一、选择题（每题 2 分，共 40 分）

1. DBMS 五大组件中，负责将声明式 SQL 转换为最优执行计划的是？

✓ 正确！ DML 编译器的核心是查询优化器，负责将 SQL 转为最优执行计划。A执行计划，C管理物理存储，D处理DDL语句。

2. "三级模式两级映像"中，提供物理数据独立性的是？

✓ 正确！ 概念模式/内模式映像提供物理数据独立性，存储结构变化不影响概念模式。

3. 关系模型中，外键的值可以是什么？

✓ 正确！ 参照完整性规定外键必须为被参照表主键中存在的值或 NULL（除非有 NOT NULL 约束）。

4. 以下哪个 SQL 语句的分类是正确的？

✓ 正确！ CREATE 属于 DDL（数据定义语言）。SELECT 是 DML，GRANT 是 DCL，COMMIT 是 TCL。

5. 关系代数中，$\sigma_{age>20}(Student)$ 表示什么操作？

✓ 正确！ $\sigma$ 是选择运算，按条件筛选行（水平切分）。投影是 $\pi$。

6. SQL 执行顺序中，HAVING 子句在什么时候执行？

✓ 正确！ 执行顺序：FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY→LIMIT。

7. 关于视图，以下说法正确的是？

✓ 正确！ 含聚合、JOIN、GROUP BY、DISTINCT 的视图不可更新。视图不存数据，可跨多表。

8. LEFT JOIN 中，当右表无匹配行时，右表列的值是？

✓ 正确！ LEFT JOIN 保留左表所有行，右表无匹配时填 NULL。

9. 关于索引，以下说法错误的是？

✓ 正确！ 哈希索引不支持范围查询（BETWEEN）、排序和前缀匹配，这是常考点。

10. 查询优化中最重要的原则是？

✓ 正确！ "尽早执行选择"是查询优化的首要原则——先用WHERE过滤减少数据量再连接。

11. 关系代数中，自然连接 (Natural Join) 的特点是？

✓ 正确！ 自然连接自动按所有同名属性等值连接，结果中去掉重复列。

12. 以下聚合函数中，哪个不考虑 NULL 值？

✓ 正确！ COUNT(*) 统计所有行（包括含NULL的行），其他聚合函数都忽略NULL。

13. SQL 中 UNION 和 UNION ALL 的区别是？

✓ 正确！ UNION 去重（需排序比较，较慢），UNION ALL 不去重（较快）。

14. 相关子查询与不相关子查询的区别是？

✓ 正确！ 相关子查询每行都重新执行内层查询（用 EXISTS），不相关子查询独立执行一次。

15. 在 SELECT 中定义的列别名，可以在哪个子句中使用？

✓ 正确！ ORDER BY 在 SELECT 之后执行，所以可以用别名。WHERE、GROUP BY、HAVING 都在 SELECT 之前。

16. B+ 树索引中，实际数据指针存储在？

✓ 正确！ B+ 树的所有数据指针都在叶节点，内部节点仅用于导航。叶节点通过链表相连支持范围查询。

17. 关于 DML 编译器，以下说法正确的是？

✓ 正确！ DML 编译器的核心是查询优化器，负责选择最优执行计划。执行由查询评估引擎完成。

18. 下列哪种连接会返回笛卡尔积？

✓ 正确！ CROSS JOIN 返回笛卡尔积（所有组合），等价于不加 ON 的 INNER JOIN。

19. SQL 中的 DISTINCT 关键字作用范围是？

✓ 正确！ DISTINCT 作用于 SELECT 列表的所有列组合。所有列都相同的行才被视为重复。

20. 关于聚簇索引，以下说法正确的是？

✓ 正确！ 聚簇索引决定了数据的物理存储顺序，因此每表只能有一个。范围查询是聚簇索引的最佳场景。

二、判断题（每题 1 分，共 10 分）

21. 视图是物理存储的虚拟表，包含实际数据。

✗ 错误！ 视图只存储定义（查询语句），不存储实际数据。每次访问时动态计算。

22. 自然连接 (Natural Join) 会自动按同名属性进行等值连接。

✓ 正确！ 自然连接自动匹配所有同名属性进行等值连接，结果中去除重复列。

23. WHERE 子句中可以使用聚合函数如 AVG()、SUM()。

✗ 错误！ WHERE 在分组前执行，不能使用聚合函数。聚合函数只能在 HAVING、SELECT 和 ORDER BY 中使用。

24. 哈希索引不支持 BETWEEN 范围查询。

✓ 正确！ 哈希索引仅支持等值比较（=、IN），不支持范围查询、排序和前缀匹配。

25. 外键值必须是被参照表主键中存在的值，不能为 NULL。

✗ 错误！ 外键可以为 NULL（除非有 NOT NULL 约束）。NULL 表示「暂未关联」。

26. SQL 执行顺序中，SELECT 在 GROUP BY 之前执行。

✗ 错误！ SELECT 在 GROUP BY 和 HAVING 之后执行。顺序：FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY。

27. B+ 树索引的叶节点通过链表相连，支持高效的范围查询。

✓ 正确！ B+ 树叶节点链表使得范围扫描非常高效，这是 B+ 树优于 B 树的关键特点。

28. COUNT(col) 和 COUNT(*) 在统计行数时结果始终相同。

✗ 错误！ COUNT(col) 忽略 NULL 值，COUNT(*) 统计所有行（包括含NULL的行）。

29. 外模式/概念模式映像提供了逻辑数据独立性。

✓ 正确！ 外模式/概念模式映像保证概念模式变化时外模式不变，提供逻辑数据独立性。

30. UNION ALL 会对结果集进行去重排序。

✗ 错误！ UNION ALL 不去重，保留所有行（包括重复行）。UNION 才会去重。

三、填空题（每题 2 分，共 20 分）

31. DBMS 五大组件分别是：DDL编译器、DML编译器、查询评估引擎、 和事务管理器。

答案：存储管理器 — 管理磁盘空间、缓冲区、文件组织和索引维护。

32. 三级模式包括：外模式、概念模式和 。

答案：内模式 — 即物理层，描述数据在存储介质上的组织方式。

33. 关系代数中， 运算相当于 SQL 中的 WHERE 子句。

答案：选择 (σ / Selection) — 按条件筛选行，是水平切分。

34. SQL 执行顺序中， 子句在 GROUP BY 之后、SELECT 之前执行。

答案：HAVING — HAVING 在分组后过滤，可以使用聚合函数。

35. 关系模型的三大完整性约束是：实体完整性、 和用户定义完整性。

答案：参照完整性 — 外键值必须存在于参照表的主键中或为 NULL。

36. B+ 树索引中，所有数据指针都存储在 。

答案：叶节点 — 内部节点仅用于导航，叶节点存储实际数据指针并形成链表。

37. 在 SQL 中， 关键字用于去除查询结果中的重复行。

答案：DISTINCT — 作用于 SELECT 列表的所有列组合。

38. JOIN 会返回两表的笛卡尔积。

答案：CROSS — CROSS JOIN 返回所有行的两两组合，无需 ON 条件。

39. 子查询中引用外层列，每行都需要重新执行的是 子查询。

答案：相关 (Correlated) — 使用 EXISTS/ALL/ANY 关键词，每行重新计算。

40. 索引的数据物理顺序与索引顺序一致，每张表只能有一个。

答案：聚簇 (Clustered) — 数据行按索引键物理排序，范围查询性能最优。

四、简答题（每题 5 分，共 20 分）

41. 简述三级模式两级映像架构，并说明两级映像分别提供什么独立性？

参考答案：三级模式：外模式（用户视图层）、概念模式（逻辑层）、内模式（物理层）。两级映像：外模式/概念模式映像提供逻辑数据独立性——概念模式变化不影响外模式；概念模式/内模式映像提供物理数据独立性——存储结构变化不影响概念模式。这种架构实现了数据与程序的分离。

42. 简述 SQL 的完整执行顺序，并说明为什么 WHERE 中不能使用 SELECT 中定义的别名？

参考答案：执行顺序：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT。因为 SELECT 在 WHERE 之后执行，所以 SELECT 中定义的列别名在 WHERE 执行时还不存在，无法引用。但 ORDER BY 在 SELECT 之后执行，所以可以使用别名。

43. 对比 B+ 树索引和哈希索引的优缺点及适用场景。

参考答案：B+ 树索引：支持等值查询和范围查询，自动平衡 O(log n)，叶节点链表支持高效范围扫描。适用场景：通用查询、范围查询、排序。哈希索引：等值查询快 O(1)，但不支持范围查询（BETWEEN）、排序（ORDER BY）、前缀匹配（LIKE）。适用场景：精确匹配（=、IN）的等值查询。

44. 什么是视图？视图有哪些优点和局限性？

参考答案：视图是基于基表的虚拟表，只存储定义不存储数据，访问时动态计算。优点：安全性（隐藏敏感列）、简化复杂查询、逻辑数据独立性。局限：含聚合/JOIN/GROUP BY/DISTINCT 的视图不可更新；每次访问需执行底层查询，可能影响性能；删除基表会导致视图失效。

五、综合题（10 分）

45. 有以下两个关系：
Student(sid, name, age, dept_id)   Department(dept_id, dept_name, building)

(1) 用关系代数写出「查询计算机系（CS）所有学生的姓名和年龄」
(2) 用 SQL 写出「查询每个系的学生人数，按人数降序排列，只显示人数大于10的系」
(3) 为上述 SQL 查询建议合适的索引策略并说明理由

参考答案：
(1) $\pi_{name,age}(\sigma_{dept\_name='CS'}(Student \bowtie Department))$
(2) SELECT dept_id, COUNT(*) AS cnt FROM Student GROUP BY dept_id HAVING cnt > 10 ORDER BY cnt DESC;
(3) 在 Student.dept_id 上建 B+ 树索引（辅助索引）加速 GROUP BY；如果 dept_name 查询频繁，在 Department.dept_name 上也建索引加速 WHERE 过滤。
