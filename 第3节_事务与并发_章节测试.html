一、选择题（每题 2 分，共 40 分）

1. ACID 中，哪个特性保证"事务要么全做要么全不做"？

✓ 正确！ 原子性(Atomicity)=All or Nothing，通过日志+UNDO实现。

2. 事务状态转换中，PARTIALLY COMMITTED 之后的下一个状态是？

✓ 正确！ 成功路径：ACTIVE→PARTIALLY COMMITTED→COMMITTED。失败路径：ACTIVE→FAILED→ABORTED。

3. 以下哪对操作不冲突？

✓ 正确！ 读-读不冲突。只有涉及写操作（读写/写写）才可能冲突。

4. 优先图中出现环说明什么？

✓ 正确！ 优先图有环=不可冲突可串行化。无环=冲突可串行化。

5. 两阶段锁 (2PL) 的增长阶段特征是什么？

✓ 正确！ 增长阶段只获取锁不释放，收缩阶段只释放锁不获取。

6. 锁兼容矩阵中，S 锁和 X 锁之间是？

✓ 正确！ S锁与X锁冲突。只有S+S兼容。

7. 严格 2PL 排他锁何时释放？

✓ 正确！ 严格2PL中排他锁在COMMIT后释放，避免级联回滚。

8. 死锁的四个必要条件中不包括？

✓ 正确！ 四个必要条件是：互斥、持有并等待、不可抢占、循环等待。可抢占会消除死锁。

9. Wait-Die 方案中，新事务等老事务时会发生什么？

✓ 正确！ Wait-Die：新等老→新死。Wound-Wait：新等老→新等待，老等新→新受伤。

10. 2PL 协议保证什么？

✓ 正确！ 基本2PL保证冲突可串行化。严格2PL才保证无级联回滚。

11. 无级联调度 (Cascadeless) 的特征是？

✓ 正确！ 无级联调度避免脏读，Ti只能读取已提交事务写入的数据。

12. ACID 中持久性 (Durability) 主要通过什么实现？

✓ 正确！ 持久性通过WAL（日志先写）+检查点+REDO恢复实现。

13. 优先图中边 Ti→Tj 表示什么？

✓ 正确！ 优先图边 Ti→Tj 表示Ti和Tj有冲突操作且Ti先执行。与等待图不同。

14. 哪个调度层次最严格？

✓ 正确！ 严格⊂无级联⊂可恢复。严格调度不允许读写未提交数据。

15. 强 2PL (Rigorous 2PL) 释放锁的时机是？

✓ 正确！ 强2PL所有锁都在COMMIT后释放，保证严格调度。

16. 等待图中出现环说明什么？

✓ 正确！ 等待图有环⇔死锁。注意与优先图的区别：优先图有环=不可冲突可串行化。

17. 以下哪个是冲突可串行化但不属于可恢复调度的情况？

✓ 正确！ A中T2在T1之前提交但读了T1的未提交数据，不可恢复（T1若回滚T2无法恢复）。

18. Wound-Wait 方案的特点是什么？

✓ 正确！ Wound-Wait优先老事务：老等新则新受伤回滚，新等老则新等待。

19. 视图可串行化与冲突可串行化的关系是？

✓ 正确！ 冲突可串行化是视图可串行化的子集。视图可串行化范围更广但判断是NP完全的。

20. 解决死锁的"检测+恢复"策略通常怎么做？

✓ 正确！ 检测+恢复：周期性地构建等待图，发现有环就回滚一个事务打破环路。

二、判断题（每题 1 分，共 10 分）

21. ACID 中的一致性 (Consistency) 完全由 DBMS 保证。

✗ 错误！ 一致性由DBMS和应用共同保证。DBMS保证完整性约束，但业务逻辑一致性需应用层保证。

22. 两个不同事务的 Read(X) 操作是冲突的。

✗ 错误！ 读-读不冲突。只有涉及写操作（读写/写写）才可能冲突。

23. 遵循基本 2PL 的调度一定是冲突可串行化的。

✓ 正确！ 这是2PL的核心保证：遵循2PL的调度一定是冲突可串行化的。

24. 优先图无环说明调度是冲突可串行化的。

✓ 正确！ 优先图无环⇔冲突可串行化。拓扑排序给出等价串行顺序。

25. 死锁预防中的"一次获取所有锁"方案不会降低并发度。

✗ 错误！ 一次获取所有锁会严重降低并发度，因为事务在开始时就要锁定所有可能用到的数据。

26. 严格 2PL 可以避免级联回滚。

✓ 正确！ 严格2PL中排他锁在提交后才释放，其他事务无法读到未提交数据。

27. S 锁和 S 锁之间是兼容的。

✓ 正确！ 多个事务可以同时持有同一数据的共享锁（读锁），读-读不冲突。

28. 等待图 (Wait-for Graph) 和优先图 (Precedence Graph) 是同一个概念。

✗ 错误！ 等待图用于死锁检测（边=等待锁），优先图用于判断可串行化（边=冲突顺序）。

29. Wait-Die 和 Wound-Wait 都保证无饥饿。

✓ 正确！ 两者都基于时间戳，老事务不会被无限延迟（无饥饿）。

30. 可恢复调度中，Ti 读取了 Tj 的数据后 Ti 可以先于 Tj 提交。

✗ 错误！ 可恢复调度要求：若Ti读取Tj的数据，Ti必须在Tj提交后才能提交。否则Tj回滚时Ti无法恢复。

三、填空题（每题 2 分，共 20 分）

31. ACID 中，I 代表 。

答案：隔离性 / Isolation — 并发事务互不干扰，通过锁/时间戳实现。

32. 事务失败路径：ACTIVE → → ABORTED。

答案：FAILED — 成功路径是ACTIVE→PARTIALLY COMMITTED→COMMITTED。

33. 两个操作冲突的三个条件：不同事务、同一数据项、至少一个是 。

答案：写 / Write — 读-读不冲突。

34. 2PL 的两个阶段是：增长阶段和 阶段。

答案：收缩 / Shrinking — 增长只获取，收缩只释放。

35. 死锁检测通过构建 图来判断。

答案：等待 / Wait-for — 有环=死锁。

36. 锁（读锁）之间是兼容的。

答案：共享 / S / Shared — S+S兼容，S+X冲突，X+X冲突。

37. 严格 2PL 中， 锁在提交后才释放。

答案：排他 / X / Exclusive — 避免级联回滚。

38. 调度不允许读取未提交事务的数据。

答案：无级联 / Cascadeless — 避免脏读导致的级联回滚。

39. Wait-Die 方案中，新事务等老事务时，新事务会 。

答案：死亡 / Die / 回滚 — 新事务比老事务年轻，所以"死亡"并重试。

40. 图用于判断调度是否冲突可串行化。

答案：优先 / Precedence — 无环=冲突可串行化。

四、简答题（每题 5 分，共 20 分）

41. 简述 ACID 四大特性及其实现机制。

参考答案：原子性：All or Nothing，通过日志+UNDO实现。一致性：事务前后数据库满足约束，DBMS保证完整性约束+应用保证业务逻辑。隔离性：并发事务互不干扰，通过锁/时间戳并发控制实现。持久性：提交后永久保存，通过WAL+日志+检查点+REDO实现。

42. 简述优先图法判断冲突可串行化的步骤。

参考答案：1.为每个事务Ti创建节点。2.找出所有冲突操作对（不同事务、同一数据、至少一个写），按执行顺序加边Ti→Tj。3.检查是否有环：无环→冲突可串行化，拓扑排序给出等价串行顺序；有环→不可冲突可串行化。

43. 对比基本2PL、严格2PL、强2PL的区别及各自保证的性质。

参考答案：基本2PL：锁在不再需要时释放→保证冲突可串行化。严格2PL：排他锁在COMMIT后释放→保证冲突可串行化+无级联回滚。强2PL：所有锁在COMMIT后释放→保证冲突可串行化+严格调度。严格程度递增，但并发度递减。

44. 简述死锁的四个必要条件和三种处理策略。

参考答案：四个条件：互斥、持有并等待、不可抢占、循环等待（破除任一可预防）。三种策略：1.预防：一次获取所有锁/超时；2.检测+恢复：定期检查等待图，有环则回滚牺牲者；3.避免：时间戳方案（Wait-Die/Wound-Wait），保证无死锁且无饥饿。

五、综合题（10 分）

45. 给定以下调度 S（按时间顺序）：
T1: R(X), W(X)   T2: R(X), W(Y)   T3: R(Y), W(Y)
具体顺序：T1:R(X), T2:R(X), T1:W(X), T3:R(Y), T2:W(Y), T3:W(Y)
(1) 画出优先图
(2) 判断 S 是否冲突可串行化
(3) 如果可串行化，给出等价串行顺序

参考答案：
(1) 分析冲突：T1:W(X)和T2:R(X)→T1→T2；T2:W(Y)和T3:R(Y)→T2→T3；T2:W(Y)和T3:W(Y)→T2→T3。优先图：T1→T2→T3。
(2) 无环，S是冲突可串行化的。
(3) 拓扑排序给出等价串行顺序：T1→T2→T3。
